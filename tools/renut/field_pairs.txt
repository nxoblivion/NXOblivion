# Oblivion (XDK 2.0.2417) device fields vs reNut/katamari (XDK 5632) and N&B (TU3, 7978) offsets.
# Format: <function>: oblivion +dec (0xHEX) <-> katamari <name> 0xHEX / N&B 0xHEX  [notes]
# N&B values come from katamari's "katamari-nx: N&B->katamari" comments in d3d_native.h / d3d_native_state.cpp / d3d.h.
# Oblivion device size 20608 (0x5080, = Zuma) vs katamari 0x5700, N&B 0x5E00.

## Ring and header (Oblivion puts the ring first; katamari puts 5 pending masks first)
KickOff/BeginRingBig: oblivion +0 (0x0) Ring <-> katamari off::Ring 0x30
KickOff/BeginRingBig: oblivion +4 (0x4) RingLimit <-> katamari off::RingLimit 0x34
KickOff: oblivion +8 (0x8) RingGuarantee <-> katamari off::RingGuarantee 0x38  [setters compare ring (+0) against +8 before writing]
AddRef/Release: oblivion +12 (0xC) refcount <-> katamari 0x3C
Pending masks: oblivion 5 qwords +16..+48 (0x10..0x30) <-> katamari 5 qwords from 0x0 (PredicatedPending2 0x28)
  observed: PS float constants dirty in +24; VS float constants, B/I constants, texture fetch ((1<<63)>>slot) in +32;
  IndxOffset bit 61 in +40; VS/PS/decl/stream/clip-plane bits (0x80, 0x100, 0x400, 0x20) in +48. Bit layouts not cross-checked against katamari.
State tables: oblivion SetRS +96 (0x60) / SetSS +484 (0x1E4) / GetRS +564 (0x234) / GetSS +952 (0x3B8)
  <-> katamari SetRS 0x40 / SetSS 0x1D4 / GetRS 0x224 / GetSS 0x3B8  [already paired by the state work; listed for completeness]
